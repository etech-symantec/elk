기존 ELK → OneClick 관리 전환 가이드

OneClick 없이 설치한 ELK를 재설치하지 않고 관리 도구에 등록하는 절차

v2.9.39 기준 · 2026-10-13 · Ubuntu 22.04/24.04

기존 ELK 등록 화면 예시

이미 설치된 ELK를 OneClick 관리에 넣을 때 보는 흐름입니다. “먼저 검사하고, 괜찮으면 등록한다”만 기억하면 됩니다.

1단계패치 메뉴에서 기존 ELK 서버 등록을 선택합니다.
2단계먼저 --inspect로 읽기 전용 검사를 합니다.
3단계문제가 없으면 --apply로 관리 등록을 진행합니다.
4단계등록 후 버전/리포트/업데이트 확인을 합니다.

실제 접속 주소: https://etech-symantec.github.io/elk/

01 · 작업 범위

기존 ELK 점검구성·서비스 읽기 전용 확인
OneClick 등록관리 도구·환경파일·백업
관리 기능 활용점검·차등 업데이트
중요: 이 가이드의 기본 작업은 기존 Elasticsearch/Kibana/Logstash를 OneClick 관리 대상에 등록(adopt)하는 것입니다. ELK 제품 버전 업그레이드가 아닙니다. Elastic Stack 버전을 실제로 변경하려면 별도의 호환성·데이터·플러그인 검토 및 계획이 필요합니다.

02 · 변경 전 확인

  • 현재 Elasticsearch / Kibana / Logstash 설치 및 서비스 동작 확인
  • 기존 설정 파일 및 인덱스/스냅샷 별도 백업 권장
  • 중요 클러스터라면 Elasticsearch Snapshot 및 복구 절차 선검증
  • /etc/elk-auto/elk.env가 이미 존재하면 adopt 대신 구버전 업그레이드 경로 확인
무엇을 하는 단계인가요? 등록 전에 현재 ELK 상태와 OneClick 설정 존재 여부를 확인합니다.
  • 서비스가 살아 있는지 확인
  • 기존 설정 파일이 있는지 확인
  • 이미 OneClick 설정이 있으면 재등록 전에 상태를 다시 확인하세요.
sudo systemctl status elasticsearch kibana logstash --no-pager
sudo ls -l /etc/elasticsearch/elasticsearch.yml /etc/kibana/kibana.yml /etc/logstash/logstash.yml
sudo test -e /etc/elk-auto/elk.env && echo "OneClick 설정 존재: 재등록 주의" || echo "OneClick 설정 없음"
버튼을 누르면 이 명령어가 바로 복사됩니다.

03 · 관리 스크립트 준비

최신 OneClick ZIP에서 _internal/core/ 폴더를 서버로 복사합니다. 이 폴더에는 elk-oneclick-adopt.sh, elk-oneclick-update.sh, elk-report.sh 등이 들어 있습니다.

무엇을 하는 단계인가요? OneClick 관리 스크립트를 기존 ELK 서버로 복사하는 단계입니다.
  • 로컬 PC에서 최신 ZIP을 푼 뒤 실행하세요.
  • 서버에는 elk-oneclick-core 폴더로 복사됩니다.
# 로컬 PC에서 ZIP을 푼 후
scp -r _internal/core USER@SERVER:/home/USER/elk-oneclick-core
버튼을 누르면 이 명령어가 바로 복사됩니다.
ZIP이 없는 상황이라면 공개 GitHub 저장소에서 동일 릴리스 파일을 확보하세요. 저장소 공개 여부와 파일 존재는 별도로 확인이 필요합니다.

04 · 읽기 전용 사전 점검

01

서버의 기존 ELK 구성 확인

무엇을 하는 단계인가요? 이 명령은 읽기 전용 사전 검사입니다.
  • 현재 ELK 경로, 포트, 서비스 상태를 보여줍니다.
  • 설정을 바꾸지 않으니 먼저 실행해도 안전합니다.
sudo bash /home/USER/elk-oneclick-core/elk-oneclick-adopt.sh --inspect
버튼을 누르면 이 명령어가 바로 복사됩니다.

ES·Kibana·Logstash 구성 경로, 포트, HTTP 상태, 서비스 활성 상태가 표시됩니다. 이 단계에서는 기존 설정을 변경하지 않습니다.

05 · OneClick 관리 등록

01

등록 적용

무엇을 하는 단계인가요? 이 명령은 기존 ELK를 OneClick 관리 대상으로 등록합니다.
  • ELK 자체를 재설치하지 않습니다.
  • 관리 명령, 리포트, 업데이트 체계가 추가됩니다.
sudo bash /home/USER/elk-oneclick-core/elk-oneclick-adopt.sh --apply --source-dir /home/USER/elk-oneclick-core
버튼을 누르면 이 명령어가 바로 복사됩니다.
02

등록 내용 확인

/etc/elk-auto/elk.env와 /etc/elk-auto/oneclick-release.env가 생성되고, 관리 도구가 설치됩니다. 기존 ELK 설정은 /var/backups/elk-oneclick-adopt/날짜/에 백업됩니다.

등록 시 INSTALL_ELASTICSEARCH=false, INSTALL_KIBANA=false, INSTALL_LOGSTASH=false를 사용하고 기존 ES/Kibana/Logstash 주요 YAML 설정은 덮어쓰지 않도록 설계돼 있습니다.

옵션 --enable-report-web은 선택 사항입니다. 활성화하면 리포트 웹 서비스가 기본 127.0.0.1:5602에 바인딩됩니다. 원격 접속은 SSH 포트포워딩 등 별도 보안 접속 방식을 권장합니다.

06 · 등록 후 확인

sudo elk-oneclick-version
sudo elk-report
sudo elk-oneclick-update --check
sudo grep -E "^(ELK_ADOPTED_SERVER|INSTALL_(ELASTICSEARCH|KIBANA|LOGSTASH)|ONECLICK_GITHUB_)" /etc/elk-auto/elk.env
버튼을 누르면 이 명령어가 바로 복사됩니다.

관리 도구 업데이트가 필요하면 sudo elk-oneclick-update --apply를 사용합니다. 이 명령은 런타임 파일을 갱신하며 기존 ELK 구성을 재설치하지 않습니다.

07 · 실제 ELK 제품 업그레이드가 필요할 때

기본적으로 sudo elk-oneclick-update --full을 실행하지 마세요. 기존 수동 구축 서버에서는 OneClick 설치 엔진이 현재 환경과 일치한다고 보장할 수 없습니다. --full은 installer 재실행을 동반하므로 기존 클러스터 구조·보안·Logstash 파이프라인·저장 경로를 먼저 검토해야 합니다.

제품 업그레이드는 다음을 별도 계획합니다: 현행 버전/대상 버전 호환성, Snapshot 검증, 플러그인·에이전트·TLS·인덱스 호환성, 서비스 중단 및 롤백 절차. OneClick adopt만으로 제품 버전이 바뀌지는 않습니다.

📁 elk.env와 SH 파일, 무엇에 쓰나요?

쉽게 말해 elk.env는 설정표, SH는 그 설정을 읽고 작업하는 실행 파일이에요.

⚙️ elk.env · 설정표

서버 주소, 시간대, 로그 폴더, MAIN/SSL/Cloud 옵션처럼 설치·운영에 필요한 값을 적어두는 파일입니다.

▶️ *.sh · 실행 파일

설정표를 읽어 설치하거나 상태를 검사하는 Linux용 스크립트입니다. 종류마다 역할이 달라요.

1. elk.env 확인·백업

설치 후 기본 위치는 /etc/elk-auto/elk.env입니다. 비밀번호와 API 키가 들어갈 수 있으므로 공개 저장소나 메신저에 파일 내용을 올리지 마세요.

서버에서 설정 파일이 있는지 확인
sudo ls -l /etc/elk-auto/elk.env
설정을 변경하기 전에 백업
sudo cp -a /etc/elk-auto/elk.env /etc/elk-auto/elk.env.bak.$(date +%Y%m%d-%H%M%S)

설정값을 바꾸더라도 모든 실행 중 서비스에 즉시 반영되는 것은 아닙니다. 항목에 따라 설정값 패치나 재적용이 필요해요.

2. 기존 ELK 등록용 SH는 어떻게 사용하나요?

elk-oneclick-adopt.sh는 이미 설치된 ELK를 다시 설치하는 파일이 아니라, OneClick 관리 도구를 연결하는 파일입니다.

먼저 기존 ELK 상태만 검사
sudo bash ./_internal/core/elk-oneclick-adopt.sh --inspect
검사 결과 확인 후 OneClick 관리에 등록
sudo bash ./_internal/core/elk-oneclick-adopt.sh --apply --source-dir ./_internal/core

등록 뒤 /etc/elk-auto/elk.env가 만들어지거나 보완될 수 있습니다. 기존 설정 백업과 설치 경로 확인을 먼저 하세요.

주의: 서버에 이미 존재하는 설정과 데이터를 보호하려면 실행 전 백업하고, 검사용 명령부터 실행하세요.
