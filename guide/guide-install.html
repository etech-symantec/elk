01 · 설치 흐름

Wizard 설정설치 항목·저장소·로그·TLS
SH/ZIP 생성원클릭 실행 파일 다운로드
Ubuntu 검증·설치서비스/인덱스/리포트 확인
대상: 신규 Ubuntu 22.04 또는 24.04 서버. Elastic Stack 기본 대상은 9.x이며, 실제 설치 버전은 Wizard 설정 및 저장소 상태에 따릅니다.

02 · 설치 전 준비

  • Ubuntu 서버의 sudo/root 권한, 고정 IP 또는 DNS, 충분한 CPU·RAM·디스크 확보
  • 방화벽에서 설치용 APT/Elastic 저장소 접근과 실제 사용할 관리·수집 포트를 검토
  • 기존 ELK 데이터가 남아 있는 서버는 신규 설치 대상이 아님 — 기존 ELK 등록 가이드 참고
  • 설치 설정의 TIMEZONE, ES_PATH_DATA, LOGSTASH_PATH_DATA 및 용량 계획 확인
로그 입력 방식(FTP/파일/TCP), TLS, 접속 포트, Elastic 인증 정보에 따라 개방할 포트가 달라집니다. 모든 포트를 일괄 허용하지 마세요.

03 · Config Wizard 사용

01

ELK OneClick Installer 열기

웹 브라우저에서 ELK OneClick Installer를 열고 ELK 자동 구성을 선택합니다.

02

기본값과 구성 선택

Elasticsearch·Kibana·Logstash 설치 사용 여부, 버전, Timezone, 디스크 경로, 보안/TLS, Logstash 입력, ProxySG MAIN/SSL/Cloud 사용 여부를 순서대로 설정합니다.

03

ProxySG 로그 사용 시 필수 확인

MAIN/SSL/Cloud의 실제 ELFF #Fields 순서와 Wizard의 포맷을 맞춥니다. localtime은 설정된 현지 시간대로 해석하고, date time은 UTC로 해석해 Kibana에 공통 Timezone으로 표시합니다.

04

원클릭 설치 파일 다운로드

Installer에서 생성한 elk-oneclick-install-*.sh 또는 설치 ZIP을 다운로드합니다. ZIP 안의 관리용 _internal/core/install-elk.sh는 단독 실행 시 elk.env가 필요합니다.

04 · 설치 실행 방법 2가지

실행 방식 선택: 아래 A. Windows CMD 원클릭 또는 B. Ubuntu 서버 직접 명령 실행 중 하나만 선택하세요. 양쪽을 모두 실행할 필요는 없습니다.

A. Windows CMD 원클릭 원격 설치

A1

Wizard에서 설치 ZIP 생성 후 압축 해제

ELK 자동 구성에서 설정 완료 후 설치 패키지 ZIP을 내려받아 Windows PC에 압축을 풉니다. ZIP 안에는 run-remote-deploy.cmd와 _internal/tools/run-remote-deploy.ps1이 포함됩니다. CMD와 _internal 폴더 구조를 그대로 유지하세요.

A2

Windows의 OpenSSH 및 서버 SSH 접근 확인

Windows 11 PC에서 ssh, scp가 사용 가능한지 확인하고, Ubuntu 서버 IP, SSH 포트, 계정 및 sudo 권한을 준비하세요.

무엇을 하는 단계인가요? 설치 전에 이 PC에서 SSH와 SCP 명령을 쓸 수 있는지 확인하는 단계입니다.
  • ssh -V : 원격 접속 명령이 있는지 확인
  • scp -V : 파일 복사 명령이 있는지 확인
  • 둘 중 하나라도 안 되면 Windows OpenSSH 기능부터 확인하세요.
ssh -V
scp -V
버튼을 누르면 이 명령어가 바로 복사됩니다.

scp -V는 버전에 따라 사용법 오류로 표시될 수 있으나 명령을 찾으면 OpenSSH 클라이언트가 설치된 상태입니다.

A3

CMD 실행

압축을 푼 폴더에서 run-remote-deploy.cmd를 실행하고 화면 안내에 따라 SSH 대상과 인증 방법을 입력하세요. 해당 CMD가 내부 PowerShell 원격 배포 스크립트를 호출해 파일 전송과 설치를 수행합니다.

무엇을 하는 단계인가요? Windows에서 설치를 시작하는 단계입니다.
  • 첫 줄: 압축을 푼 설치 폴더로 이동
  • 둘째 줄: 설치 도우미 CMD 실행
  • 실행 후 화면 질문에 맞춰 서버 정보만 입력하면 됩니다.
cd /d C:\ELK-OneClick
run-remote-deploy.cmd
버튼을 누르면 이 명령어가 바로 복사됩니다.

폴더 경로는 실제 압축을 해제한 위치로 변경하세요. 실행 후 전송·검증·설치 결과 및 오류 출력을 확인하세요.

B. Ubuntu 서버에서 SH 명령 직접 실행

B1

Wizard에서 단일 설치 SH 생성

Config Wizard에서 설정한 뒤 원클릭 설치 SH 파일을 다운로드하세요. 단일 SH는 생성된 구성값을 포함한 설치 실행 파일입니다.

B2

서버로 전송

Windows PowerShell 또는 로컬 터미널에서 SSH/SCP로 Ubuntu 서버의 홈 디렉터리에 전송합니다.

무엇을 하는 단계인가요? 생성한 설치 파일을 Ubuntu 서버로 복사하는 단계입니다.
  • USER는 서버 계정명으로 바꾸세요.
  • SERVER는 서버 IP 또는 호스트명으로 바꾸세요.
  • 파일명은 실제 받은 elk-oneclick-install-*.sh 이름으로 바꾸세요.
scp elk-oneclick-install-*.sh USER@SERVER:/home/USER/
버튼을 누르면 이 명령어가 바로 복사됩니다.

USER와 SERVER는 실제 접속 정보로 변경하세요. SSH 포트가 다르면 scp -P 포트를 이용하세요.

B3

SSH 접속 후 사전 검증 및 설치

무엇을 하는 단계인가요? 서버에 접속해서 검사 후 실제 설치를 진행하는 단계입니다.
  1. SSH로 서버 접속
  2. 설치 파일이 있는 폴더로 이동
  3. --validate로 먼저 오류 확인
  4. --local-install로 실제 설치 실행
ssh USER@SERVER
cd /home/USER
sudo bash elk-oneclick-install-*.sh --validate
sudo bash elk-oneclick-install-*.sh --local-install
버튼을 누르면 이 명령어가 바로 복사됩니다.

ZIP 안의 _internal/core/install-elk.sh를 직접 실행하려면 별도 elk.env 등의 환경 구성이 필요하므로, 초회 설치는 Wizard가 생성한 단일 SH를 권장합니다.

주의: 명령 예시의 SH 이름은 Wizard가 생성한 실제 파일명에 맞게 바꿔야 합니다. --validate는 사전 검사이며 실행 환경 및 서비스 설치 성공을 보장하지 않습니다. 운영 환경 적용 전 백업 및 유지보수 시간을 확보하세요.

05 · 설치 후 검증

무엇을 하는 단계인가요? 설치가 끝난 뒤 정상 동작을 확인하는 단계입니다.
  • 버전 확인
  • 리포트 확인
  • 서비스 상태 확인
  • 업데이트 점검 가능 여부 확인
sudo elk-oneclick-version
sudo elk-report
sudo systemctl status elasticsearch kibana logstash --no-pager
sudo elk-oneclick-update --check
버튼을 누르면 이 명령어가 바로 복사됩니다.

웹 리포트를 활성화한 경우 설정된 ELK_REPORT_WEB_HOST/ELK_REPORT_WEB_PORT에서 상태를 확인합니다. ProxySG를 사용하면 MAIN/SSL/Cloud 수신 → 처리 대기 → 인덱스 흐름을 확인하세요.

GitHub 최신 파일 확인은 etech-symantec/elk의 main 브랜치를 기준으로 하며, 대상 저장소에 해당 파일이 실제 게시돼 있어야 합니다.

📁 elk.env와 SH 파일, 무엇에 쓰나요?

쉽게 말해 elk.env는 설정표, SH는 그 설정을 읽고 작업하는 실행 파일이에요.

⚙️ elk.env · 설정표

서버 주소, 시간대, 로그 폴더, MAIN/SSL/Cloud 옵션처럼 설치·운영에 필요한 값을 적어두는 파일입니다.

▶️ *.sh · 실행 파일

설정표를 읽어 설치하거나 상태를 검사하는 Linux용 스크립트입니다. 종류마다 역할이 달라요.

1. elk.env 확인·백업

설치 후 기본 위치는 /etc/elk-auto/elk.env입니다. 비밀번호와 API 키가 들어갈 수 있으므로 공개 저장소나 메신저에 파일 내용을 올리지 마세요.

서버에서 설정 파일이 있는지 확인
sudo ls -l /etc/elk-auto/elk.env
설정을 변경하기 전에 백업
sudo cp -a /etc/elk-auto/elk.env /etc/elk-auto/elk.env.bak.$(date +%Y%m%d-%H%M%S)

설정값을 바꾸더라도 모든 실행 중 서비스에 즉시 반영되는 것은 아닙니다. 항목에 따라 설정값 패치나 재적용이 필요해요.

2. 설치용 SH는 어떻게 실행하나요?

웹에서 생성한 단일 설치 SH에는 설치에 필요한 설정이 함께 담깁니다. 내려받은 파일을 Ubuntu 서버로 옮긴 다음, 실제 파일 이름으로 실행하세요.

먼저 설치 가능 여부만 검사
sudo bash 실제_다운로드한_설치파일.sh --validate
검사가 끝나면 실제 설치
sudo bash 실제_다운로드한_설치파일.sh --local-install

반면 ZIP 안의 _internal/core/install-elk.sh는 개발·관리용 원본 설치기로, 별도의 elk.env를 인자로 받아 실행하는 형태입니다. 초보자는 단일 설치 SH 또는 CMD 원클릭 설치를 권장해요.

주의: 예시의 실제_다운로드한_설치파일.sh는 직접 만든 설치 파일명으로 바꿔야 합니다. 기존 운영 서버에 신규 설치 SH를 무심코 실행하지 마세요.
