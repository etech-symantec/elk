이미 ELK가 설치된 서버 · 한눈에 보는 설명

꼭 알아두세요! 기존 ELK를 OneClick 관리 대상으로 등록하는 작업이며, ELK 제품 자체 버전을 올리는 작업은 아니에요.

① 순서대로 따라 하기

1
기존 상태 확인

Elasticsearch·Kibana·Logstash 상태와 중요한 설정 백업을 확인해요.

2
관리 파일 준비

OneClick ZIP의 _internal/core 폴더를 서버로 복사해요.

3
먼저 검사하기

읽기 전용 --inspect로 상태를 확인해요.

4
관리 대상으로 등록

결과를 확인한 다음 --apply를 실행해요. ELK 자체를 재설치하지 않아요.

5
등록 확인

관리 명령과 점검 리포트가 동작하는지 살펴봐요.

② 필요한 명령어 복사하기

예시의 파일명이나 경로는 실제 생성한 설치 파일과 서버 위치에 맞게 바꿔 주세요.

읽기 전용 검사
이 명령은 읽기 전용 검사입니다.
  • 현재 ELK 상태만 확인합니다.
  • 설정을 바꾸지 않으니 먼저 실행해도 안전합니다.
sudo bash ./_internal/core/elk-oneclick-adopt.sh --inspect
버튼을 누르면 이 명령어가 바로 복사됩니다.
관리 등록
이 명령은 기존 ELK를 OneClick 관리 대상으로 등록합니다.
  • 재설치가 아니라 관리 기능을 붙이는 작업입니다.
  • 검사 결과를 본 뒤 실행하세요.
sudo bash ./_internal/core/elk-oneclick-adopt.sh --apply --source-dir ./_internal/core
버튼을 누르면 이 명령어가 바로 복사됩니다.
등록 후 확인
이 명령들은 등록이 잘 되었는지 확인합니다.
  • 버전 확인
  • 점검 리포트 확인
  • 업데이트 점검 가능 여부 확인
sudo elk-oneclick-version
sudo elk-report
sudo elk-oneclick-update --check
버튼을 누르면 이 명령어가 바로 복사됩니다.

📁 elk.env와 SH 파일, 무엇에 쓰나요?

쉽게 말해 elk.env는 설정표, SH는 그 설정을 읽고 작업하는 실행 파일이에요.

⚙️ elk.env · 설정표

서버 주소, 시간대, 로그 폴더, MAIN/SSL/Cloud 옵션처럼 설치·운영에 필요한 값을 적어두는 파일입니다.

▶️ *.sh · 실행 파일

설정표를 읽어 설치하거나 상태를 검사하는 Linux용 스크립트입니다. 종류마다 역할이 달라요.

1. elk.env 확인·백업

설치 후 기본 위치는 /etc/elk-auto/elk.env입니다. 비밀번호와 API 키가 들어갈 수 있으므로 공개 저장소나 메신저에 파일 내용을 올리지 마세요.

서버에서 설정 파일이 있는지 확인
sudo ls -l /etc/elk-auto/elk.env
설정을 변경하기 전에 백업
sudo cp -a /etc/elk-auto/elk.env /etc/elk-auto/elk.env.bak.$(date +%Y%m%d-%H%M%S)

설정값을 바꾸더라도 모든 실행 중 서비스에 즉시 반영되는 것은 아닙니다. 항목에 따라 설정값 패치나 재적용이 필요해요.

2. 기존 ELK 등록용 SH는 어떻게 사용하나요?

elk-oneclick-adopt.sh는 이미 설치된 ELK를 다시 설치하는 파일이 아니라, OneClick 관리 도구를 연결하는 파일입니다.

먼저 기존 ELK 상태만 검사
sudo bash ./_internal/core/elk-oneclick-adopt.sh --inspect
검사 결과 확인 후 OneClick 관리에 등록
sudo bash ./_internal/core/elk-oneclick-adopt.sh --apply --source-dir ./_internal/core

등록 뒤 /etc/elk-auto/elk.env가 만들어지거나 보완될 수 있습니다. 기존 설정 백업과 설치 경로 확인을 먼저 하세요.

주의: 서버에 이미 존재하는 설정과 데이터를 보호하려면 실행 전 백업하고, 검사용 명령부터 실행하세요.
